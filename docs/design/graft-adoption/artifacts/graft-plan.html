Graft adoption · plan & gap analysis

What graft fills, what the suite keeps, and how the deep layer runs on our side

The verdict from reading graft's real output: it carries the generic code graph — functions, classes, signatures, six edge kinds — but a route handler is just a function node and a model is just class X(Base). The framework facts (routes, tables, FKs, fetch paths) and the process data (tests, board, ledger, evidence) are ours to keep. graft retires the re-derivation, not the whole generator layer.

The deep layer — run it on our subscription, tied to a beat

graft's --deep is three stateless "read code → write prose" calls through one swappable ChatModel interface. No special access — we can run the exact prompts on the Claude subscription and write results into graft's body_hash-keyed cache (Path A, in-bounds).

Regeneration cost — cheap enough to hook

S

Structural build ~ms · free

graft's AST index is freshness-first (~3ms/query, cached). Cheap enough to hook on every beat — execute, review, red — so the structural map is never stale.

Hook: a PostToolUse rebuild (graft ships this) + a suite pre-beat freshness check.
D

Deep prose (LLM) incremental · subscription

The first --deep pass is the one-time cost (~8.3k nodes). After that, summaries cache on body_hash — only changed files re-summarize, so a commit touching 5 files runs ~5 calls. Cheap enough to hook on /gabe-commit.

Hook: post-commit, deep-summarize the diff's files on the subscription → write graft's cache. Never blocks the commit.
