Command Center · architecture pivot

The map moves to graft. The Center stays ours.

Today the suite rebuilds a codebase map from scratch every regen, and the process spine rescans the code every task — because nothing forces it to read the map. After adoption, graft owns the facts and enforces its own use; the Command Center becomes graft's renderer, and the spine queries the map instead of grepping. The loop closes.

Recommendation How to install

  1. Pilot on gustify, on a branch. graft is a dev-session tool — install it where it runs, not a throwaway copy: npm i @nanonets/graft + graft init. The branch keeps it fully reversible; graft/ stays gitignored, the .claude/ enforcement is committed (that's the point).
  2. Run graft build --deep once with a cheap Claude model (Haiku) for the summary/crux prose. Summaries cache on body_hash, so only changed nodes re-summarize after — the first pass is the one-time cost, later builds are incremental.
  3. Measure a few real sessions — does injection fire, do tool-calls drop (graft claims 46% fewer)? If it delivers, merge + propagate to gastify. If not, drop the branch — zero residue.
  4. Then the suite work — P1 consume graft facts, P2 frontend as a graft reader, verified against the compiler oracle, with the same badge-vs-panel audit that caught the 32 defects.
