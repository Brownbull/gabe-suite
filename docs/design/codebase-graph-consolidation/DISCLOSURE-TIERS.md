# Disclosure Tiers — design proposal (2026-08-27, NOT built)

> Operator ask: the gap fixes will add noise; design a priority/tier system for nodes and
> connections that discloses progressively (calls · access · FK first) without overwhelming.
> Status: PROPOSAL — awaits the operator's decisions below and a "land it". Artifact: Disclosure Tiers.
> Method: rule-based tier v1/v2 measured over the committed gustify map, then an 8-agent design
> panel (4 lenses · 3 judges · synthesis); judges split 2–1 for the hybrid the synthesis adopted.

## The model

PATH-ROLE LADDER — one emitter-computed integer per node and per wire (`tier` 0–4 + a `why` code), one ceiling in the station (`window.__uniLevel`), the existing WALK PIN as the only exemption. It is P2's ladder (a tier is a ROLE ON A PATH: skeleton · fabric · request path · context · residue) with P3's property discipline where a property suffices (fabric = d2w set | own write op | ANY handler — no reverse-BFS, no degree, no fan-in, no score), P1's seams (visN + a wire twin of __uniRelHide, disclosed-edge depth BFS, the __uniGoto kind-OFF fix, the legend's 3-state left UNTOUCHED), and P4's feedback grammar (one topbar control, the five-word gate vocabulary, .hidnote[data-gate], selection-scoped tier ghosts, level 4 == today byte-for-byte, capsules counted on the disclosed set). Re-measured as S on the committed gustify map (scratchpad/tiers-S.py, reusing tiers-compare's loader + noise sim and tiers-v2b's _bkCollect replica): L0 110 nodes/66 wires · L1 248/401 · L2 339/714 · L3 463/942 · L4 489/946 (== today). Walkability by construction then measured: 34/34 write paths intact at L1 (template POST /setup/complete hops [0,1,1,1,0,1,1]), 67/67 derived backend journeys + 30/30 curated workflow endpoints walkable at L2 with zero pins, 26/67 fully walkable at L1 (the read legs pin). Stability under the +426 synthetic-noise sim (13 endpoints · 238 unclaimed fns · 162 methods, seed 7): 13/489 original nodes move (2.7%), every one a formerly-isolated fn that the noise WIRED (4→3) or gave a root caller (4→2) — a change on the node itself, never a population shift (B's quantiles moved 78 unrelated nodes; v2b's ≥2-wire tie-break moves 15). Why this over the pure-property H (0 churn): H's journey guarantee is curated-only (workflows.js coupling; the 67 derived journeys were never measured for it) and its floor BFSes station-derived wires the emitter would have to re-derive; the reach closure from roots IS the request path, it is the same handler-rooted walk `behind` already runs at emit, future roots (boot seeders, dispatch targets) enter with no new rule, and 'reached from GET /recipes at hop 3' is a sentence. Why this over v2b: every handler is fabric (an endpoint never discloses without its first hop — the v1 lesson generalised, +24 read handlers, 224→248 at L1), the 3-vs-4 degree tie-break is replaced by 'isolated' (0 wires), and the floor table is emitted once so the adapter carries no copy.

## Node rules
- entity → T0 always [skeleton:entity].
- endpoint → T0 always, wired or not [skeleton:route] — the coming +13 unclaimed-file routes too; their `__unclaimed__` home is the FLEET row's business, never the tier's (v1's degree≥2 demotion of 5 routes is gone).
- model → T0 if ≥1 model↔model FK wire in either direction, the external proxy not counting [skeleton:fk-linked] (43/55 today); else T1 if any fn writes it or a writes_to rollup names it [fabric:written | fabric:written(rollup-only — the writing fn is undrawn)] (6); else T2 if only read [request:read] (6); else T3 [context:orphan-table]. Degree never decides a model's tier — FK, write, read do.
- function (and the coming class `method`, `unclaimed`, `minted`) → T1 if d2w==0 or it holds its own write op [fabric:writer] (101); T1 if d2w=n [fabric:d2w=n] (7); T1 if it is an endpoint's handler [fabric:handler] (24 read handlers — an endpoint's first hop discloses WITH it, so the v1 template break cannot recur for any route); else T2 if REACHED from a ROOT over calls/dispatches, hop recorded [request:reached@hN] (58; roots = handlers today, boot seeders class 6 + dispatch targets class 5 later — same walk, no new rule); else T3 if it has ≥1 wire of any kind [context:unreached(k wires)] (4); else T4 [residue:isolated] (16). Role, access kind, fan-in and the census status never move a fn's tier — the path does; that is what keeps +238 unclaimed fns + 162 methods from flooding L1–L2: only the ones a route actually runs through surface.
- schema → CONTRACT tier (3 recommended; 2 = variant A) if a route consumes / responds with / serializes / touches it [contract:consumed-by-route] (79); T3 if only nested [context:nested-only] (34); T4 if unwired [residue:unwired-schema] (10). A contract wraps the path; it is never a hop, so it never breaks walkability.
- web screen → T2 if ≥1 bridge (its fetch matched a route) [request:fetches-route] (27); else T3 [context:unmatched-fetch] (5) — the hollow-dashed screens stay reachable one level down.
- external → T3 [context:fk-proxy] (2) — the real FK is the cross-entity model→model wire at T0.
- FE pieces (component/hook/store/route/module/type) → the same ladder with FE routes as roots: T2 = a screen or its direct user on a bridge path, T3 = reachable from a route, T4 = the rest; `type` stays held-off (load gate) as today. NOT measured on the 1,077-piece FE arm — it keeps its own switches (Types, capsules, R1–R4) until measured.
- A node with NO `tier` field (an old feed, or `stats.tiers` absent) reads as `untiered` = never hidden by the level, never promoted into the skeleton; with no `stats.tiers` the level control does not render and the station behaves exactly as today.
- The legend's critical SOLO fold is a separate axis applied INSIDE the disclosed level (26 solos today, all ≤ T2, 0 at L1 → L2 at critical = 164 drawn fns); `n.__solo` is never folded into `tier`, and the client never mutates `n.tier` — the displayed tier must always equal the emitted `why` (P1's client bump rejected).
- Order of gates in visN is the 'why is this hidden?' answer, stated once in its header: kind OFF (absolute; functions/types OFF = unloaded) › PIN (journey step · search/goto · ghost click · double-click · _walkGo; Esc clears) › LEVEL (`n.tier > __uniLevel`) › critical solo fold › node override › fleet entity∧cluster (show∧planets) › [capsule fold = structural, pre-visN] › focus-hide (unless HL.set-exempted). Every surface names the FIRST failing gate with the same five words — kind · level · solo · fleet · focus.

## Connection rules
- ONE formula: tier(e) = max(FLOOR[kind], tier(source), tier(target)) — a wire never discloses before both of its ends.
- FLOOR table, emitted ONCE as `stats.tiers.floors` and read by the adapter (no duplicate table in the client): fk 0 · handler 1 · fnwrites 1 · writes_to 1 · calls 1 · dispatches 1 · fnreads 1 (the operator's fn→model reads; measured +61 wires at L1, 340→401, and L1-complete journeys 18→26/67 vs floor 2) · reads_from 2 · bridge 2 · depends 2 · consumes / resp / serializes / touches = CONTRACT (3 recommended; touches keeps that floor until the consumes/resp split lands) · nests 3 · imports 3 · fe rels per the FE ladder.
- calls needs no d2w-band rule (v1's band rule is what contradicted its node rule): a calls wire is tier 1 iff both ends are fabric, otherwise it takes the request-path tier of its non-fabric end — 67 calls wires at L1, all 145 at L2.
- Fan-in demotion, the R2 rule generalised and the ONLY relative input anywhere: a depends / fecall wire into a sink with fan-in ≥15 takes floor 3 — the gate fn keeps its own tier (build_auth_context writes User → T1, its 47 coming Depends wires are context). Access wires are EXEMPT: today's ≥15 sinks are Recipe 38 · CookingSession 35 · User 32 · PantryItem 32 · UserDietaryProfile 28 · external:auth 27 · Location 17 · CookingPhoto 17 — the operator's top connection must never be demoted.
- Station-DERIVED wires (endpoint→handler, fn→model fnreads/fnwrites minted from access.ops in _buildFnData, capsule `bundle`) are not in the feed: the adapter applies the same formula at link build from the ends' emitted tiers + the emitted floors (bundle = min over its members); recomputed only on structural change (fn/type toggle, capsules, boot) beside __uniComputeSolo — never per frame.
- Lit or selected beats the level: a wire above the ceiling still draws when a journey lit it (HL.links) or it is __uniSelLink — the identical exemption R1–R4 already carry at the three seams. A pinned NODE does not by itself re-ink its above-level wires (P4's 'either end pinned' rejected: a pinned hub re-inks 30+ context wires mid-walk); double-click's forced `.wires` flag is unchanged.
- Beam 0 stays the absolute per-kind wire gate (the wire twin of legend OFF) and the LAST gate, inside connectorWire after hf — it hides even lit wires (rollups never light on a journey); unchanged and documented as a feature.
- Rollups (writes_to / reads_from) keep beam 0 by default; their tier only matters when the beam is turned on.
- Wire gate order, stated once: both ends _nodeVisibleFn ∧ visN().wires › __uniRelHide (R1–R4, fe only) › __uniLvlHide (new) unless lit/selected › hf (_hlLinkF: focus rest) › beam.

## Risks
- The post-gap projection is a synthetic ceiling: the noise sim wires EVERY synthetic fn to a random existing fn (60% as callee), so 262/426 land at T2 → L2 ~630; the property-only H projection says 566. Real unclaimed fns may be less reached — but if the gap fixes make them reachable, L2 is exactly the tier that grows fastest, and capsules (threshold 80 on the disclosed set) must carry that mass. Put the measured L2 number in every gap-fix commit.
- The tier inherits the emitter's honesty floor: a writer graft/access cannot see (gap classes 2 ORM idioms · 3 Depends · 5 event bus) has d2w None → T2/T3 and is hidden at the L1 boot. Not a new lie (that fn is already drawn green on the d2w heat) and now it carries a `why` — but the fix is the emitter roadmap (ORM symtab, Depends hop, schema→model edge), never a client heuristic; ghosts + double-click + search keep it one click away meanwhile.
- Churn is small but non-zero: 13/489 (2.7%) under +426 nodes, every one a formerly-isolated fn that gained a wire (4→3) or a root caller (4→2). Proofs that pin COUNTS per tier will re-pin on every regen that wires new code — pin RULES and the walkable ratios, not tier totals.
- Boot at L1 hides the read legs: only 26/67 derived journeys are fully inside L1 (67/67 at L2). A user browsing a read endpoint at L1 sees route + handler, then a ghost only once something is selected. The hidnote's [raise level to 2] chip and the journey pin are the mitigations; if the operator finds L1 too bare, the decision is the boot level, not the ladder.
- Boot moves from 'everything' to L1 → the 431 static pins + render proofs and verify-backend-journeys' boot-visibility contract all perturb; re-anchor ONCE with GABE_UNI_LEVEL=4 (the recorded critical-by-default lesson) and re-pin the four already-decayed proofs in the same pass; the boot read must precede the +400 ms function-load step or the first fold and first render disagree (a flash).
- The disclosed-edge depth BFS changes what 'depth 3' means under a low level (3 DISCLOSED hops) — a behaviour change to an existing switch; small, stated in the card, but a proof pinning HL.set sizes will move.
- The ghost predicate rework touches the one hand-picked scene group (__uniBgClick picks stubs with priority over hulls) — regression risk in picking; the render proof must click a tier ghost, and selection-scoped stars must rebuild on selection change (already inside updateConnectors' rebuild, not a new per-frame hook).
- CONTRACT=3 delays an endpoint's request/response schemas to L3 — the codebase-graph station's screen→endpoint→schema reading is not visible at the default; the serializes/touches-split gap fixes land as contract wires too, so this choice governs most of the coming schema noise either way.
- Reach makes 'why hidden' depend on graft call coverage (101 of 145 calls are inferred): a fn on a real request path that graft did not wire is T3 with why `context:unreached` — honest and locally explainable ('no drawn caller'), but the answer points at the map, not the code.
