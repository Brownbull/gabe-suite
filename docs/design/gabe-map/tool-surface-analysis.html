Which suite processes should be tools

The suite is about to get its first MCP server, gabe-map. Before building more, this page asks which of the suite's 58 candidate processes deserve to be tools an agent reaches for mid-reasoning, and which must stay hooks, gates, scripts or rulings. Every row was scored by three independent judges on importance, impact, cost and risk; open a row for the pain it touches, who would call it, what goes in and out, what happens if it is never built, and the reasoning behind its verdict.

The frame

what a tool is for, and what it is not

Tools inform. Rails hold. Nags remind.

  • A tool answers a question the agent has while thinking — who owns this path, who calls this symbol, what reads or writes this model, which cases cover it, how stale is the map. It is reached for because it is the cheapest move, not because a spec step said so.
  • A tool is not a rail. It fires only when the model chooses it, so every lifecycle moment (commit, push, plan writes, publish, regen) stays on hooks and gates that fire on the event.
  • A tool is not a writer of project state. The suite's lie-blocking hooks watch the harness's own Write/Edit/Bash calls; an MCP tool that wrote .kdbp files would slip past them until the hook matchers are extended.
  • A tool is not a data dump. The map is ~540K tokens against a 25k-token result cap: every answer projects, caps, names its caps, and stamps how fresh the map is.
  • A tool is not graft. The suite's tools add what graft cannot answer — entity ownership, cases, drift, the second search arm, the delta feedback — and never duplicate graft's own server, which the red spec rules out.

How much context do the tools cost — answered from the table

Always-on is the price paid every session before any call: each tool's name, description and input schema sit in the model's tool list. The always-on ctx column estimates it per tool (12 for the name + 55 for a ≤200-character description + 20 + 30 per parameter; the design caps descriptions at 200 characters). Per call is the result size when the tool is actually used — bounded by the harness at 25k tokens and, by design, far below it with every list capped and the cap named.

Two facts decide "can we have them all". First, Claude Code defers tool schemas when a session carries many MCP tools: only the names stay in context (~15 tokens each) until the model loads one on demand — observed in this session, where dozens of MCP tools were listed as deferred. Second, a deferred tool is also less discoverable, and discovery is the whole point of gabe-map. That is why the design holds one server at ≤7 tools, and why the analysis proposes the later kdbp-state readers as a sibling server rather than growing this one.
