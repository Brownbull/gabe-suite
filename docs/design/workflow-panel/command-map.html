2 · The two axes — this is the "mesh"

The six part buttons and the command panel answer two different questions, and the page never said so.

Part buttons = WHICH PART you read. Data · Schemas · Functions · Tests · Widening · Security. One at a time, the middle panel. Unchanged.

Command = WHICH PATH is in force. ways the request can end. Pick one and it stays in force while you change parts; every part then marks what is on that path.

The matrix layout draws exactly this grid — a row per path, a column per part; a cell lit when that part has facts for that path. Clicking a cell does both: it selects the path AND opens the part.

Where it got confusing: of the 15 verbs on the card ALSO open a part (Show writes → Data · preconditions, gates, findings → Security · declared, tests, untested → Tests · Open the handler → Functions). So a part can be reached from the buttons and from the card. That is the overlap you felt; it is a fact of the build, not a design ruling yet.

3 · How to move — top to bottom

  1. Pick a layout in the rail's command block cardstripladdermatrix

    All four share one selection. Whatever you pick in one, the others show.

  2. CARD — 15 verbs, then the paths
    keyverbwhat it doesopens a part?badge

    Press Q (Walk a path) and the same 15 squares become the paths, one cell each — status, kind glyph, name. The bottom-right square is always the corner: B Back on the path grid (up to the verbs, the path stays), B Clear on the verb card. Esc clears from anywhere.

  3. STRIP — the paths always visible

    The paths sit in a row under the part buttons; the card stays at the right. Click a cell: same as picking a path on the card.

  4. LADDER — where a path ends

    rungs in request order (middleware → security → dependency → body-parse → validation → handler → uncaught → the return at the foot), the exits hung on the rung they leave from. Click an exit: the rungs above light, the rungs below dim, the portrait shows the Exit record. W / E step to the previous / next exit. With "walking: replay" the bead walks the rungs on the one clock.

  5. MATRIX — path × part

    cells. A number in a cell = how many of that part's things are on that path; hollow = none. Click a cell → that path is in force AND that part opens.

5 · Your idea — the part buttons inside the command section

Three shapes it could take. None is chosen; each is a rail option to build so you can look at it beside the current one.

A · a parts row on the card

The card grows a top row of six part squares (the same SC2 squares). The bench keeps its row too, or drops it ("part buttons: bench · card · both"). One place to read AND act.

B · the matrix headers ARE the buttons

In the matrix layout the six column heads become the part buttons; the bench row folds away. The grid then is the whole console: pick a row, pick a column.

C · the verbs stop opening parts

Keep the buttons where they are and take the part-jump out of the eight verbs (they only select; you open the part yourself). Removes the overlap instead of moving anything.

Say which of A · B · C you want to see (any or all) and it gets built as an option, the same way the rest was.
