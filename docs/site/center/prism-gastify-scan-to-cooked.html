gastify: scan → cooked, with every number ghosted

Eight machines take a photographed receipt to a cooking event and back into a proficiency score. The shape is real. The numbers are not here — gastify lives in another repository — so every measured field renders as a named absence instead of a figure nobody could trace.

A floor with no numbers cannot show a bottleneck, which is exactly what this page demonstrates: every machine looks equally important. That is the failure P1 predicts when the measured-number field is empty, shown rather than described.

This is the same grammar as the other pages with one field removed. Every machine still names what it consumes and what it produces — that is structural, and structure survives the trip between repositories. The measured number does not, so it is drawn as ⌀ rather than guessed at.

Read the floor and notice what you cannot do: you cannot say which machine is the bottleneck, which one is worth optimising, or which one is doing most of the work. Eight machines, all apparently equal. That is P1's claim about the measured-number field, demonstrated instead of asserted.

What this page found out about the gate

verify-prism.mjs passes this page. Every stage carries a data-num, so check 3 is satisfied — by the string ⌀ not measured here. The gate checks that a number field is present, not that it holds a number, and a page could pass it with invented figures just as easily as with honest absences.

That is a real limit, found by building the page rather than by reading the checker. Closing it means either a provenance field per number, or a data-num-source the gate can resolve — a decision for the skill, not for this page. Recorded here so it is not rediscovered a third time.
