settings.json — a table, not a program

Two events are wired in this repo: UserPromptSubmit, and SessionStart with matcher compact. Both run the same command — cat .claude/register-core.md — with a 5-second timeout. The second exists because compaction drops the payload, and a rule that survives everything except a context compaction is a rule that quietly stops applying halfway through a long session.

the hook script — where the ghost is

Seven scripts live in scripts/hooks/kdbp/. direction-guard.sh is 16 lines, and its ninth is [ -d "$ROOT/.kdbp" ] || exit 0. Ruling R8 says this repository never carries .kdbp/, so in this repo the guard exits silently on every prompt, forever. It is correct code that cannot run here.

the injector — the machine that changes the payload's nature

Bytes on stdout go in; a rule inside the model's context comes out. This is the identity change that makes the chain worth drawing: nothing downstream can be inspected with a file read, because the payload is no longer on disk.

the model's turn — unpowered, and honestly so

The four rules arrive. Whether they change the answer cannot be tested by a fixture, because no fixture can make a model deterministically fail to honour an instruction. The suite's rule for this is explicit: a gate that cannot fail is non-evidence. So this machine is amber, not green, and the enforcement ledger classifies its rules as prompt-only rather than enforced.

a rule in the turn's context
produces
a named next move

the skill — back to something you can read

Once a skill is named, the payload is a file path again: 28 skills are addressable, each one a directory with a SKILL.md the harness loads. The chain becomes inspectable at exactly this point, which is why the ledger's evidence starts here rather than one machine earlier.

the ledger row — the claim, and its bucket

119 rules are classified across four buckets: enforced, hardenable, prompt-only, and falsely claimed. This line's own rules land in prompt-only. A row that claimed enforced for machine 5 would be the fourth state — broken — and the reason the ledger has a bucket for it at all.

The reason this subject was chosen

An injected instruction is the hardest payload to draw: it has no size, no file, and no place you can point at after machine 4. Drawn as a floor, the awkwardness becomes the finding — the chain is fully provable for three machines, unprovable for one, and dead in this repository at a gate that reads [ -d .kdbp ]. A concept map of the same seven boxes would show seven identical rectangles joined by seven identical arrows.
