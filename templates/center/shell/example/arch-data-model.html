Code Data model

DB entities and API shapes — each names its file and the endpoints that touch it

A field typed with another documented class LINKS to it (violet) instead of repeating its structure. Examples are synthetic — derived from Literal values and field-name heuristics, never real user data.
Type colors — one hue per family, deeper = the wider type: int float · Decimal numeric · date · time datetime temporal · str bytes · Text textual · bool · list · dict · Literal structured · UUID identity · None nullable. An uncolored token is a domain alias (an enum defined in this codebase).
Insight icons — the DATA-MODEL lens; the same shape runs over other member kinds later (functions · methods), scoped, never mixed:
  • model — a persisted DB entity: lives in a table, owns FKs.
  • schema — an API / pipeline shape: crosses a boundary, owns no storage.
  • base — derives from NOTHING: no FK out, no field typed by another documented class; a foundation others build on.
  • N god-class flag — field count ≥ 15; the number that makes it a split candidate below.
  • Class N% closest structural twin — % = shared fields over the union (Jaccard); a ≥80% pair becomes a merge candidate below.
  • orphan — zero API usage AND zero internal references; becomes a deprecation candidate below.
  • Usage bars: teal = api (endpoint touches + FK in) · violet = internal (mapped backend files referencing the class). Api-silent is not dead; only a true orphan is.
