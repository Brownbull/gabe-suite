# The representation ladder — how a page should be structured

> Source: every notebook subject climbs the same ladder (NN: circle sketch →
> ∂ chains → `neuron.DELTA` → gradient ledger → handwritten backprop();
> graphs: drawing → adjacency matrix → path trace → code; WCM: entity cast →
> prose flow → word-cycle → numbered diagram → one-page spec). Load when
> structuring a page or a section; this is the missing macro-structure behind
> the "visualizations that show nothing" verdict.

## The ladder

drawing / geometry → symbolic form → owner.field notation → table / ledger →
code / runnable → the screen.

- **No rung skipped** — a reader lost at rung 4 climbs down one rung, not
  back to zero.
- **Every rung kept** — earlier rungs stay on the page (or one click deep);
  the finished floor alone is the top rung with the ladder sawn off, which is
  exactly what the operator called indigestible.
- A page need not carry all rungs, but must know which rungs it shows and
  which page (or inspector) holds the ones below.

## The ordering law

**One worked case fully expanded FIRST → exhaustive enumeration of the
siblings → the generalization LAST.** (w1 end-to-end, then "…tweking
w2/w3/b1…" for every parameter, then "Pattern from backpropagation".)
The pattern is *extracted*, never asserted before its evidence; leading with
the general machine row inverts the operator's absorption order.

## The numbered walk

A static diagram earns numbers: circled 1…N turning the graph into a guided
tour (the WCM diagram walks 1–17; decision diamonds carry yes/no plus a named
consequence — penalty · deny · accept). The walk is the static twin of the
scrub bar — on any surface that cannot animate, number it.

## Iterated pictures are an estate

The same picture drawn again — draft → cleaner → richer — is versions, not
waste (WCM ×4 passes; Linkchain Core/Idea/System). New notation may appear
only in later passes (dashed vs solid arrows arrived at pass 3). Keep the
passes reachable; the newest one is the cover, not the replacement.

## Focus gravity wells — the overall picture comes first

A **well** is one big abstraction that covers almost all the concepts from a
single point of view — the whole picture at LOW detail, framed by *what is
happening*, not by what things are. The reading order is: fall into the well
first, then visit each concept in detail — below it in the same article, or
as sibling pages when the details outgrow one page. A seat's gravity world IS
its well: one well per seat, the seat's question as the frame. Never open on
a detail; the well is the hook every detail hangs from, and a detail without
its well above it is the double-click problem in page form.

## The one-page spec (what an index page wants to be)

A whole system held in one glance: the estate tree + a routes/parts table +
a "you can:" capability list + the one-line main objective + wireframes of
the surfaces. (YelpCamp on a single sheet.) A section index that is only a
link list is under-built against this bar.
