# The seat archetypes — the transfer roster

> Source: the Catan roster the operator ruled "all six very good", built to
> rename onto any application; icons are the suite-level set (inline Lucide
> strokes, `.gvi`). Load when choosing WHOSE question a page answers, or when
> seating a fresh subject.

## The six seats

| archetype | icon | the question shape | Catan exemplar | refuses to read |
|---|---|---|---|---|
| end user | single user | what do I do, right now, without embarrassment? | the new player | theory, probability tables |
| admin / operator | user group | how do I run this for other people? | the table host | strategy — referee first |
| power user | target | where is the edge nobody computed? | the strategist | rules recaps, flavour |
| compliance / security | scales | what exactly is permitted, per the text? | the rules lawyer | analogies, anything not in the text |
| architect | drafting compass | why does this system hold together? | the designer | single-run anecdotes |
| investor / stakeholder | briefcase | why does this keep earning its place? | the publisher | depth that won't fit on the box |

## The reading order is the seat order

Play it → run it → win it → adjudicate it → understand it → sell it
(end user · admin · power user · compliance · architect · investor).
The journey is the taxonomy — never staple a second initial/advanced layer on
top; it duplicates this axis and drifts from it.

## Seating a new subject

1. Fill each seat with a person who could actually show up (name their
   moment: "first game tonight", "third game this month").
2. Give each seat ONE question, in their words, with a success criterion and
   a refuses-to-read line — the refusals prevent every page serving everyone.
3. Assign each seat its ranked gravity world (~5 bodies from the census).
4. **Run the mass test** — one high-pull body through all six seats; six
   different readings or the roster isn't real.
5. Cap by usefulness: name the seat you cut (Catan cut the spectator) so the
   cut stays visible.

## Page-kind tendencies (from the queue, not laws)

- end user → console ("how does one move happen")
- power user → article over the numbers (edges, priced)
- architect → console with a return hop (the loops)
- investor → article (the story the numbers tell)
- admin / compliance → often PROSE (checklist, reference table) — expect the
  STOP to fire, and let it.
